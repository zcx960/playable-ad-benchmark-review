# 证据、参数与表述口径

## 证据等级

从高到低使用：

1. **实际操作与连续观察**：可描述触发过程、状态变化、节奏和同步关系。
2. **同阶段截图/录屏**：可描述画面、位置、可见动画；不能据此声称隐藏规则。
3. **页面代码或资源核对**：可补充次数、容量、间隔、速度等参数；需要说明来自核对，不等同于玩家体验。
4. **基于品类经验的建议**：只能写“建议/推荐/首轮基准”，不能写成现状或竞品事实。

## 参数写法

- 竞品实测：`竞品每辆车需求 6 桶，完成后产出 10 枚金币。`
- 代码核对：`页面玩法模块中的基准产油间隔为 0.7 秒，可作为首轮调参参考。`
- 修改建议：`建议资源吸附飞行控制在 0.25—0.4 秒，后续结合屏幕尺寸复测。`
- 未验证：`本轮未验证完整解锁流程，以下为待实测建议，不作为现状结论。`

## 可复用参数类型

- 次数：命中次数、产出份数、交付数量、金币数量。
- 时间：前摇、白闪、回弹、吸附、批次间隔、启动延迟、首次奖励时间。
- 空间：搜索半径、摇杆死区、最大拖动半径、相对屏宽、UI 安全区。
- 状态：缺料、运行、暂停、满仓、可购买、已完成。
- 同步：实体数量、计数、进度、液位、音效、货币到账。
- 节奏：首次移动、首次采集、首次转化、首次奖励、首次解锁。

## 数值使用限制

某项目中的“3 次命中、5 份资源、6 桶交付、10 枚金币”等只能是该竞品的参考案例，不得默认套用到其他游戏。数值建议必须与项目容量、移动距离、屏幕大小和广告时长一起判断。

## 事实与推断分离

推荐使用以下标签：

- `已实测`：实际操作中观察到。
- `可见`：截图或录屏直接可见。
- `参数核对`：代码或资源中确认。
- `建议`：本次提出的修改值。
- `待验证`：当前证据不足，需要下一轮确认。

不要写“玩家一定会流失”“留存一定提升”等无法由本次试玩证明的结论。改写为可观察风险，例如“首次操作入口不明确，测试者可能无法开始移动”。
